# 预热闸门：什么时候别开口

「先想起来再开口」不等于「每轮都先翻一遍」。这套东西里最容易搞砸的地方，是**端得太多**。
这份文档写清楚现在这道闸怎么判定，以及怎么用你自己的日志把它调对。

## 判定顺序

每一轮按这个顺序走，先命中先返回：

1. **每日预热**（每天第一次说话）：重要的事前几条 + 昨天的记录。定数，零检索。
2. **状态问题**：话里有「还差什么 / 还没做 / 下一步 / 进度到哪」→ 直接读 `statusFile` 的「还没做」段。
   这类问题问的是**现在**，不是**过去**，检索再准也不如直接看状态。
3. **没在问旧事**：话里没有旧事信号（以前/上次/上回/记得/说过/原话/第几版……）→ 一句不端。
4. **闲聊**：短句、问候、情绪、日常动作 → 不端。
5. **检索**：排除 `exclude` 里的文件（默认 `AGENTS.md`），按分数分三档：
   - ≥ `fullMin` → 端命中的块
   - ≥ `hintMin` → 只留一句「备好了，按需看」
   - 否则 → 不响
6. **同话题抑制**：这一轮命中的块和上一轮重合 ≥ 60% → 不重复端。

## 为什么要有第 3 步

2026-11 拿 85 轮真实发言回放：只按分数端，端整段占 60%，其中绝大多数轮次人家根本没问旧事；
真正用上的只有 1/54。加上旧事信号的闸之后，端整段降到 6%，一句提示 16%，**八成轮次安静**。

安静不是失败。陪伴体不需要每句话都掏档案——它只在你说「你上次不是说……」的时候接得上。

## 用日志调你自己的闸

每次预热都写一行 JSON 到 `$HOME/prefetch.log.jsonl`，字段：

| 字段 | 意思 |
| --- | --- |
| `tier` | `full` / `hint` / `none` / `status` |
| `reason` | 为什么没端：`no-old-signal` / `smalltalk` / `same-topic` |
| `confidence` | 最高分 |
| `daily` | 这轮有没有带每日预热 |
| `ms` | 耗时 |

调法（跟校准阈值一样，先看数据再动手）：

1. 跑两周，攒几十条真实轮次；
2. 挑出「该端却没端」和「端了没用」的，各标 10 条；
3. 只看这两堆，别一张表调三个旋钮；
4. 一次只改一个：先改闸门的词表，再改阈值，最后才碰 `k`。

**样本不够就别调**。我们踩过一次：拿修指标之前的脏数据去调门槛，差点把 `fullMin` 从 0.52 提到 0.55——那会把本来能命中的全压掉。先修尺子，再调门槛。

## 配置

```json
{
  "exclude": ["AGENTS.md", "HANDOFF.md"],
  "statusFile": "HANDOFF.md",
  "fullMin": 0.52,
  "hintMin": 0.48,
  "k": 3
}
```

- `exclude`：每轮都在系统提示里的文件，别再进候选。
- `statusFile`：状态文件，「还差什么」类问题直接读它的「还没做」段。
- 阈值请拿自己语料校（`bench/calibrate.mjs`），默认值只保证中文语料上「闲聊基本不触发」。

## 一句话

预热的目的是「该想起来的时候想得起来」，不是「什么都先端出来」。
**安静**也是一种正确输出。
